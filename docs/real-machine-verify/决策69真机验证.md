## 方法：真实输入 + 慢动作截图

与浏览器 mock（`motion_check.mjs` 分段区，58 项中的 5 项）同源同参，但在真实
WebView2 里重放，并补上 mock 做不到的三件事：

- **CDP `Input.dispatchMouseEvent` 真实鼠标点击**触发滑动（不是 JS click）；
- **关闭行为切换经真实 IPC 落盘 settings.json**（轮询隔离根内文件验证）；
- **`Page.reload` 后滑块首帧即对齐持久化值**——首挂载测量路径在真窗口成立，
  不从 0 滑入、不落在旧位。

键盘漫游用 CDP `Input.dispatchKeyEvent` 发真实 `ArrowRight`（方向键立即选中、
焦点跟随）。减少动态用 `Emulation.setEmulatedMedia` 仿真。

**慢动作截图**：CDP 截图有 ~200ms 合成延迟，320ms 的动画等快门到时已落定。
把滑块引用的 `--motion-spring` token 临时改 4s（纯 CSS 变量覆盖，真实窗口真实
合成器，只是时间膨胀），在行程中段（600ms）与过冲峰（2s）各拍一帧，拍完恢复。
CDP `Animation.setPlaybackRate` 对 CSS transition 不可靠（实测滑块停在起点），
不用。

真机特有的坑（脚本已处理）：

- 设置页的「关闭行为」卡片在首屏之外——CDP 鼠标事件按视口坐标派发，必须先
  `scrollIntoView` 再取坐标，否则点击在屏外落空；
- `Page.captureScreenshot` 会瞬时改视口抓全页、恢复时重置滚动位置——证据截图
  必须先拍再滚动取点击坐标，顺序反了点击落空；
- `Page.bringToFront` 后第一张合成帧偶尔是陈旧的（实测整窗发白）——先预热
  等一帧再拍 before。

## 顺带发现（测试基建，非产品 bug）

1. **WebView2 profile 不受 LOCALAPPDATA 覆盖**：WebView2 按 bundle 标识符把
   用户数据目录落在真实 `%LOCALAPPDATA%\com.leogene.mousetool-theme`，此前
   各真机脚本的外观偏好 localStorage 实际写进了用户真实 profile。已修：
   `lib.mjs` 的 `launchApp` 补 `WEBVIEW2_USER_DATA_FOLDER` 指进隔离根。
2. **外观持久化真机复证正常**：一次性探针（深色 → `Page.reload`）6/6 通过，
   localStorage 与选中态跨 reload 一致——`theme-mode.ts` 无恙。此前一轮验证
   曾见 reload 后回退「跟随系统」，系 `taskkill /F` 硬杀 + WebView2 localStorage
   异步落盘导致未提交写入丢失的**测试基建现象**，不是产品 bug（真机脚本
   硬杀收工是既定约定，结论不受影响）。

## 结论

真机 WebView2 的采样数据与浏览器 mock（`motion_check.mjs` 58 项中的分段区）
逐项一致（320ms spring / 过冲 100.8→92 / 宽度拉伸 88→64 / 落位对齐）——

真实 IPC 落盘、reload 首帧对齐、减少动态兜底均成立。
