## 方法：CDP 探针 + reload 确定性重放

开屏发生在启动最初 ~1s，CDP 接入常常赶不上冷启动首播，且固定等待等待的竞态
不可靠。脚本改用**确定性重放**：`Page.addScriptToEvaluateOnNewDocument` 给
每个新文档注入 rAF 逐帧探针（记录 `[data-splash]` 的出现 / 开始退场 / 中间态
opacity / 卸载四个时刻），`Page.reload` 重放一次——重放与冷启动走**同一条
React 挂载路径**，时间线可复现。减少动态用例用 `Emulation.setEmulatedMedia`
仿真 `prefers-reduced-motion: reduce`。

## 测量方法的坑（记给后续脚本）

- **真机脚本必须先 `assertNoRunningInstance`，且所有失败分支也要 killApp**：
  单实例互斥会让脚本拉的实例秒退转交（CDP 永远等不到、测量全废），失败分支
  不清理还会留下残留进程占着互斥——首轮测量就是这么废掉的。
- 直接 `spawn` exe 与 `cargo run` 拉起的实例行为一致（CDP 调试端口都能开），
  测量脚本可绕开 cargo 的 target 目录锁与后台构建并行。
- `Emulation.setEmulatedMedia` 的 `prefers-reduced-motion` 仿真在 WebView2 上
  可用；不可用时脚本跳过该项而不是误报。
