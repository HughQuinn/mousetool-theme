## 过程中发现并修复的真 bug（非脚本问题）

1. **跨线程 ShowWindow 第一次调用被吞**：`hide_window_to_tray` 最初在
   `spawn_blocking` 线程里调 `window.hide()`——Win32 的起始显示惯例会让「非创建
   线程对这扇窗的第一次 ShowWindow」静默无效，线程池换线程后再次失效，表现为
   藏窗随机不生效（应用侧 `is_visible` 已为 false 与否无法预测）。修复：改为
   `run_on_main_thread` 在主线程执行 hide，托盘同步跟在同一闭包里保证
   「先藏窗、后按可见性补托盘」的顺序。
2. **二次启动唤不回隐藏窗（既有 bug，决策 12 的老路径）**：`activate_existing`
   的跨进程 ShowWindow 从同步 `SW_RESTORE` / `SW_SHOW` 到 `ShowWindowAsync`、
   先显示后抢前台等组合全部实测无效——同样的 `ShowWindowAsync(SW_RESTORE)` 从
   PowerShell 发出却能生效，根因未完全定位。改为**命名事件方案**：第二实例
   `SetEvent` 即退，首个实例的守护线程等到信号后在主线程同步执行 `show_window`
   （创建者线程显示自己的窗口，不经过任何跨进程显示路径）；首个实例是旧版本
   （没有等待线程）时退回原 ShowWindowAsync 兼容路径。

## 测量方法的坑（记给后续脚本）

- **.NET `Process.MainWindowHandle` 不能当可见性判据**：窗口隐藏后它仍然非零，
  且进程内还有 WebView2 宿主的无标题可见顶层窗口会被它抓到——必须
  `EnumWindows` 按标题定位主窗口 + `IsWindowVisible`。
- PowerShell 读 ps1 的编码链路脆：helper 用 node 写 BOM + UTF-8；中文标题等
  字面量放进 C# 的码点数组（`new string(new[]{(char)0x9F20,...})`）最稳。
- React 受控组件：两次程序化点击之间要留渲染间隙（≥300ms），否则闭包读到旧
  state——「不再询问」勾选后立即点动作按钮会按未勾选执行。

**覆盖了浏览器 mock 覆盖不到的路径**：真实 WM_CLOSE 拦截（`on_window_event` 的
CloseRequested 分支）、真实事件 `close-ask` 的跨进程投递、真实窗口隐藏 / 托盘
按需创建、二次启动唤回的完整单实例链路、settings.json 真实落盘与跨重启持久化、
`exit_app` 的真实进程退出。
